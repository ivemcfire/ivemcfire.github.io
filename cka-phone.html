the L3 wallRecite the from: geometry: allow pods job=probe in ns metrics only. AND vs OR — where do the dashes go?
ingress:
- from:
  - namespaceSelector:          # dash = starts the ONE from-item
      matchLabels:
        kubernetes.io/metadata.name: metrics
    podSelector:                # NO dash = AND (same item)
      matchLabels:
        job: probe
  ports:                        # sibling of from:
  - protocol: TCP
    port: 80

Second dash on podSelector = OR = allows every pod in metrics AND every job=probe pod anywhere. The ns label goes UNDER matchLabels (07-13 slip).

Why must you always prove the DENY on a NetworkPolicy, not just the allow?

An OR-bug policy, a selector that matches nothing, and a dead CNI all look IDENTICAL from the allowed side: the probe succeeds. Only the blocked probe distinguishes "policy works" from "policy silently no-ops".

07-14Local PV on node01, no dynamic provisioning. Which volume type, which extra block, which reclaim policy — and which docs page?
spec:
  local:                    # NOT hostPath!
    path: /mnt/disk
  persistentVolumeReclaimPolicy: Retain
  nodeAffinity:             # REQUIRED for local
    required:
      nodeSelectorTerms:
      - matchExpressions:
        - {key: kubernetes.io/hostname, operator: In, values: [node01]}

Docs: Concepts → Storage → Volumes page, #local section — NOT the Persistent Volumes page. SC pair: provisioner: kubernetes.io/no-provisioner + volumeBindingMode: WaitForFirstConsumer (both TOP-level keys).

PVC with volumeName: set + SC is WaitForFirstConsumer. When does it bind?

IMMEDIATELY — explicit volumeName: pre-binds and short-circuits delayed binding. Pending only happens for unbound/dynamic claims. (Bound PVC then reports the PV's size, not the request — normal.)

false greenk auth can-i list pods --as=system:serviceaccount:fin:auditor returns yes. What does that NOT prove?

That the SA exists. --as string-matches the username against bindings — a typo'd or never-created SA still returns yes.

Pair it with k get sa -n fin. Your 07-05 slip: SA metric-reader vs binding subject metrics-reader — green check, broken RBAC.

RBAC chain in ns finance for SA auditor: recite all 4 commands — where does -n go?
k create sa auditor -n finance
k create role pod-auditor --verb=list,get --resource=pods -n finance
k create rolebinding audit-bind --role=pod-auditor \
  --serviceaccount=finance:auditor -n finance
k auth can-i list pods \
  --as=system:serviceaccount:finance:auditor -n finance

-n on ALL of them (×3 creates + the check); SA subject = ns:name; bind YOUR role, not admin.

You edited a ConfigMap that a running deployment consumes as env. Is the app updated?

No. Env-consumed CM/Secret values are baked at container start — k rollout restart deployment X or nothing changed. Confirmed 2026 exam gotcha.

Delete a static pod. How — and what never works?

mv its file out of /etc/kubernetes/manifests/ on the node. k delete pod never works — the kubelet recreates it from the file; edits go in the FILE too.

The task directory has a kustomization.yaml. Which flag — and what's the reflex error?

k apply -k ./dir (preview: k kustomize ./dir). Reflex error = muscle-memory -f, a reported recurring exam trap.

lookup-classetcd snapshot save needs 4 flags. Name them + where the values live. (Status/restore: how many certs?)
etcdctl snapshot save /opt/backup.db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \

Values readable off /etc/kubernetes/manifests/etcd.yaml (grep listen-client / pki paths). save = mTLS to the live server; status/restore = offline file ops, ZERO certs, just --data-dir. ETCDCTL_API=3: export once per question.

Pod ran with --restart=Never, now status Error. logs --previous errors out. Why?

--previous needs a RESTARTED container (CrashLoop). restart=Never containers die once — there is no previous instance. Plain k logs reads the dead container.

Started-then-died + restarting = --previous. Died once, no restart = plain logs. You reached for --previous twice on 07-05.

HPA on deployment web: min 2, max 6, target 70% CPU. One command + the two reasons TARGETS shows <unknown>.
k autoscale deployment web --min 2 --max 6 --cpu 70%

<unknown> = no metrics-server OR no CPU request on the pods (the % is measured against the request). v1.35: --cpu, the old --cpu-percent is deprecated.

Native sidecar: where does the container go, what makes it "native", and what proves it worked?

An initContainers entry with restartPolicy: Always (only legal there). Proof = pod reaches 2/2 Running — a non-native init running tail -F would wedge at Init:0/1 forever.

Helm: render a chart's manifests to a file WITHOUT installing. And the CRD-skip trap?
helm template NAME repo/chart --version X -n ns > out.yaml

--skip-crds only skips a chart's native crds/ dir; charts that TEMPLATE their CRDs (ArgoCD) need the chart value, e.g. --set crds.install=false. Reflex: helm show values chart | grep -A5 crds.

Selector ≠ pod labels — same root cause as RS "selector does not match template labels". Fix the selector or the labels; endpoints repopulate on their own.
