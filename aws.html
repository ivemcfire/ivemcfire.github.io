00 — The object graph

A1 · A3 · A8Read first

Network — what contains what, and what only points at what

IAM — three objects and two gates between a policy and a box

Create order — dependencies first

 1  VPC                 create-vpc
 2  subnets ×2          create-subnet                one AZ each
 3  public IPs          modify-subnet-attribute --map-public-ip-on-launch ×2
 4  internet gateway    create-internet-gateway + attach-internet-gateway
 5  route table         create-route-table + create-route + associate-route-table ×2
 6  security group      create-security-group + authorize-security-group-ingress
 7  key pair            create-key-pair > ~/.ssh/key.pem ; chmod 400
 8  IAM                 create-policy, create-role, attach-role-policy,
                        create-instance-profile, add-role-to-instance-profile
 9  S3                  create-bucket (LocationConstraint), versioning, public-access-block
10  AMI id              ssm get-parameters   # never hardcode an ami-
11  instance            run-instances --iam-instance-profile Name=…

Destroy order — dependents first, and nothing cascades

 1  instances           terminate-instances + wait   # an attached ENI blocks the subnet and the SG
 2  object versions     list-object-versions + delete-objects, then the delete markers
 3  bucket              delete-bucket                # refuses while anything is left
 4  key pair            delete-key-pair ; rm the local .pem
 5  role out of profile remove-role-from-instance-profile
 6  instance profile    delete-instance-profile
 7  policy off role     detach-role-policy
 8  role                delete-role
 9  policy              delete-policy
10  security group      delete-security-group        # the default SG dies with the VPC
11  route table         disassociate-route-table ×2, delete-route-table
12  IGW                 detach-internet-gateway, delete-internet-gateway
13  subnets             delete-subnet ×2
14  VPC                 delete-vpc

Gotchas

  • AWS never cascades. Every containment and attachment is unwound by hand. Three of the fourteen steps are detachments, not deletions — role out of profile, policy off role, IGW off VPC.
  • A versioned bucket keeps a delete marker for every deleted object, and those block delete-bucket exactly like objects do. Run the delete loop twice: Versions, then DeleteMarkers.
  • ParamValidation: expected one argument means a shell variable was empty, not that the flag was wrong.
  • IAM is eventually consistent. A role used in the same breath as it was created gets a spurious AccessDenied — wait and retry. Scripts need a sleep; Terraform retries for you.
  • The main route table and the default security group cannot be deleted. They die with the VPC, and a teardown script should expect those two refusals.
  • A half-failed imperative script leaves orphans, and re-running it creates duplicates. This is the entire argument for declarative state.
Docs: docs.aws.amazon.com/vpc/latest/userguide/ · docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_use_switch-role-ec2.html

01 — Account bootstrap

Day one

Order — nothing gets created until the budget alarm exists

1. Sign up, Free plan, root MFA immediately
2. Root account: never used again after step 3
3. IAM user <admin-user> + AdministratorAccess + MFA + access key
4. Budget alarm BEFORE any resource
5. CLI profile, then verify

Budget alarm

Billing → Budgets → Create budget → Cost budget
  amount: 20 USD/month
  alerts at 50% / 80% / 100% actual → email
Billing → Preferences → Receive free tier usage alerts

CLI

sudo dnf install awscli2
aws configure --profile ivx          # key, secret, eu-west-1, json
aws sts get-caller-identity --profile ivx
export AWS_PROFILE=ivx

Verify before building anything

aws budgets describe-budgets \
  --account-id $(aws sts get-caller-identity --query Account --output text)
aws iam list-mfa-devices

Gotchas

  • Access keys in a repo = account compromised in minutes. Bots scan GitHub continuously.
  • Billing data is us-east-1 only. Cost Explorer looks empty if you filter by region.
  • Accounts opened after 2025-07-15 have no 12-month EC2 free tier — $100 credits at signup, $20 each for five Console Home tasks. The Free plan account closes at 6 months unless upgraded.
  • Deleting an account's resources is not closing the account. Bills continue.
  • eu-west-1 vs eu-west-2 typo = resources you can't find and don't delete.
Docs: aws.amazon.com/free · awscli.amazonaws.com/v2/documentation/api/latest/reference/

02 — IAM

A2 · A5 · A8

The four nouns

ThingCredentials?Holds policies?Note
Useryes — password / AKIA keysyespermanent identity
Groupnoyesbag of users, no login of its own
Policy—is oneJSON: Allow/Deny × Action × Resource
Roletemporary — ASIA + SessionTokenyes, plus a trust policyassumed, expires ~1h

Permission chain: user → group → attached policy. Break any link and it's AccessDenied.

Policy document

{"Version":"2012-10-17","Statement":[
  {"Sid":"x","Effect":"Allow","Action":"s3:GetObject",
   "Resource":"arn:aws:s3:::bucket/*"}]}
  • Version is the policy language date, always 2012-10-17 — not the policy's own version (VersionId: v1).
  • Managed = has its own ARN, reusable. Inline = embedded, no ARN, dies with the principal.
  • AWS-managed ARN arn:aws:iam::aws:policy/… · yours arn:aws:iam::<acct>:policy/…

A role is TWO documents

trust policy      (AssumeRolePolicyDocument) — WHO may assume it
  Principal: {"Service":"ec2.amazonaws.com"} or {"AWS":"arn:...:user/name"}
permission policy — WHAT it may do, attached normally

ARN shapes

arn:aws:iam::<acct>:user/<name>   # IAM is global, region field empty
arn:aws:s3:::<bucket>             # the bucket    (s3:ListBucket)
arn:aws:s3:::<bucket>/*           # the objects   (s3:GetObject)

Commands

aws sts get-caller-identity                    # WHO AM I. always first
aws iam list-attached-user-policies  --user-name X
aws iam list-groups-for-user         --user-name X
aws iam list-attached-group-policies --group-name X   # managed
aws iam list-group-policies          --group-name X   # inline
aws iam get-policy         --policy-arn A      # metadata -> DefaultVersionId
aws iam get-policy-version --policy-arn A --version-id v1
aws iam create-role --role-name N --assume-role-policy-document file://trust.json
aws iam attach-role-policy --role-name N --policy-arn A
aws iam update-assume-role-policy --role-name N --policy-document file://trust.json
aws sts assume-role --role-arn R --role-session-name test

Gotchas

  • not authorized to perform: sts:AssumeRole usually means the role's trust policy refused you, not that you lack permissions. Misleading wording.
  • Admin (Action: *) does not override a trust policy.
  • IAM is eventually consistent — change a trust policy, assume immediately, get a spurious AccessDenied. Wait ~10s. Bites in Terraform too.
  • IAM never validates that a Resource exists. A typo'd bucket is a silent no-op.
Docs: docs.aws.amazon.com/service-authorization/latest/reference/ for actions per service · Console → IAM → Policies → Visual editor generates clean JSON.

03 — VPC & subnets

A3 · A4 · A10Bills

What makes a subnet public

route table entry: 0.0.0.0/0 → igw-xxxx

# that is the whole answer. not the name, not auto-assign IP

Build one by hand

aws ec2 create-vpc --cidr-block 10.0.0.0/16
aws ec2 create-subnet --vpc-id vpc-x --cidr-block 10.0.1.0/24 \
  --availability-zone eu-west-1a
aws ec2 create-internet-gateway
aws ec2 attach-internet-gateway --vpc-id vpc-x --internet-gateway-id igw-x
aws ec2 create-route-table --vpc-id vpc-x
aws ec2 create-route --route-table-id rtb-x \
  --destination-cidr-block 0.0.0.0/0 --gateway-id igw-x
aws ec2 associate-route-table --route-table-id rtb-x --subnet-id subnet-x
aws ec2 modify-subnet-attribute --subnet-id subnet-x --map-public-ip-on-launch

Getting out from a private subnet

PathCostUse for
NAT gatewayhourly + per GBgeneral outbound internet
Gateway endpointfreeS3, DynamoDB only
Interface endpoint (PrivateLink)hourly + per GBother AWS APIs

Inspect

aws ec2 describe-vpcs --query 'Vpcs[].[VpcId,CidrBlock,IsDefault]' --output table
aws ec2 describe-subnets --filters Name=vpc-id,Values=vpc-x \
  --query 'Subnets[].[SubnetId,CidrBlock,AvailabilityZone]' --output table
aws ec2 describe-route-tables --filters Name=vpc-id,Values=vpc-x

Gotchas

  • A VPC CIDR cannot be changed after creation. You can only add secondary CIDRs. Plan it once.
  • AWS reserves 5 addresses per subnet — a /28 gives you 11 usable, not 16.
  • Subnets are AZ-scoped; VPCs are regional. A subnet never spans AZs.
  • A NAT gateway is roughly $32/month before a byte moves, and it's per-AZ for real HA. This is the most common surprise line on a lab bill.
  • An Elastic IP that isn't attached to anything is billed hourly. Free only while in use.
  • The default VPC comes fully wired with public subnets. Fine for a first launch, wrong for anything you'll show an interviewer.
Docs: docs.aws.amazon.com/vpc/latest/userguide/ — "VPC with public and private subnets" is the reference topology.

04 — Security groups & NACLs

A1

The difference, in one table

Security groupNetwork ACL
Attaches toENI (instance, endpoint, LB)subnet
Statestateful — replies allowed automaticallystateless — replies need their own rule
Rulesallow onlyallow and deny
Evaluationall rules, any match winslowest rule number first, first match wins
Can referenceanother security groupCIDR only
Defaultno inbound, all outboundallow everything both ways

Commands

aws ec2 create-security-group --group-name web --description "web tier" --vpc-id vpc-x
aws ec2 authorize-security-group-ingress --group-id sg-web \
  --protocol tcp --port 443 --cidr 0.0.0.0/0

# the idiomatic pattern: db allows web, by group, not by IP
aws ec2 authorize-security-group-ingress --group-id sg-db \
  --protocol tcp --port 5432 --source-group sg-web

aws ec2 describe-security-groups --group-ids sg-web \
  --query 'SecurityGroups[].IpPermissions'

Gotchas

  • Referencing a security group instead of a CIDR is the answer interviewers want — instances come and go, the group reference survives.
  • Stateless NACLs need an outbound rule for ephemeral ports 1024-65535 or replies are dropped. Outbound works, the answer never arrives.
  • A NACL deny beats any security group allow. NACLs are the blunt instrument — use them for a CIDR block ban, not for app rules.
  • Removing the last inbound rule doesn't remove the group's outbound allow-all. Check both directions.
  • A hang means dropped (security group or NACL). A refused connection means something answered. That distinction finds the layer in seconds.
Docs: docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html · …/vpc-network-acls.html

05 — S3

A7Bills

Two CLIs, on purpose

aws s3 ls s3://bucket/prefix/      # high level: ls cp mv sync rm
aws s3 sync ./dir s3://bucket/dir/
aws s3api get-bucket-policy --bucket b     # low level: everything else

Who can make it public — four layers

LayerCheck
Account Block Public Accessaws s3control get-public-access-block
Bucket Block Public Accessaws s3api get-public-access-block --bucket b
Bucket policyaws s3api get-bucket-policy --bucket b
Object ACL (legacy)aws s3api get-bucket-acl --bucket b

Lock it down

aws s3api put-public-access-block --bucket b \
  --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

aws s3api put-bucket-versioning --bucket b --versioning-configuration Status=Enabled
aws s3api put-bucket-encryption --bucket b --server-side-encryption-configuration \
  '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'

Gotchas

  • Bucket ARN and object ARN are different resources. s3:ListBucket needs arn:aws:s3:::b; s3:GetObject needs arn:aws:s3:::b/*. Most broken policies are this.
  • Bucket names are globally unique across all AWS accounts — the storage is regional, the namespace is not.
  • A versioned bucket won't delete until every version and delete-marker is purged. aws s3 rb --force misses versions.
  • Egress to the internet is the line item people forget. Storage is cheap; getting data out is not.
  • Incomplete multipart uploads keep billing invisibly. Set a lifecycle rule to abort them after 7 days.
Docs: docs.aws.amazon.com/AmazonS3/latest/userguide/ — "Blocking public access" and "Bucket policy examples".

06 — Cost control

A6The whole card

Where the money actually goes in a lab account

ResourceWhy it bills
NAT gatewayhourly + per GB, whether used or not
Unattached Elastic IPhourly, precisely because it's idle
Detached EBS volumeper GB-month; survives instance termination
Load balancerhourly + capacity units
CloudWatch log groupingestion + storage, forever if retention is unset
RDShourly even when idle; snapshots outlive the instance

Check spend from the CLI

aws ce get-cost-and-usage \
  --time-period Start=$(date +%Y-%m-01),End=$(date -d tomorrow +%Y-%m-%d) \
  --granularity MONTHLY --metrics UnblendedCost

# same, split by service — this is the one that answers "why $300"
aws ce get-cost-and-usage \
  --time-period Start=$(date +%Y-%m-01),End=$(date -d tomorrow +%Y-%m-%d) \
  --granularity MONTHLY --metrics UnblendedCost \
  --group-by Type=DIMENSION,Key=SERVICE

Teardown proof — run before you close the laptop

aws ec2 describe-instances \
  --query 'Reservations[].Instances[?State.Name!=`terminated`].InstanceId'
aws ec2 describe-volumes --filters Name=status,Values=available
aws ec2 describe-addresses --query 'Addresses[?AssociationId==`null`]'
aws ec2 describe-nat-gateways --filter Name=state,Values=available
aws elbv2 describe-load-balancers --query 'LoadBalancers[].LoadBalancerName'

Gotchas

  • Cost Explorer lags up to 24h. A teardown that looks free today can still land tomorrow.
  • Budgets alert, they don't stop anything. Nothing in AWS caps spend by itself.
  • Terraform destroy leaves anything it didn't create — console-made test resources, orphaned snapshots, log groups.
  • Tag every lab resource at creation. Untagged resources can't be found by Cost Explorer and won't be found by you either.
Docs: Billing → Cost Explorer (us-east-1 only) · docs.aws.amazon.com/cost-management/latest/userguide/
